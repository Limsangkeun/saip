# 학습 노트 블로그 (saip) 설계

작성일: 2026-10-23

## 1. 의도와 이유

사용자는 Spring 기반으로 일해 온 자바 개발자다. 정리하는 일을 귀찮아해서 배운 내용을 남기지 못하고, 같은 내용을 매번 다시 검색하게 된다.

이 프로젝트는 두 가지를 동시에 해결한다.

1. **기록 비용을 0에 가깝게 만든다.** 사용자는 Claude Code와 대화하며 개발한다. 사용자가 "이거 블로그에 올려줘"라고 말하면 Claude Code가 그 대화에서 배운 내용을 노트로 정리해 블로그에 올린다. 사용자가 직접 글을 쓰지 않아도 된다.
2. **실제 배포를 처음부터 끝까지 경험한다.** 블로그를 로컬 실행부터 Docker, AWS, 도메인과 HTTPS, CI/CD까지 단계별로 직접 배포한다. 각 단계에서 쓰는 도구와 개념은 이 블로그의 노트로 남긴다.

성공의 기준은 이렇다. 사용자가 무언가를 다시 찾아볼 때 검색 엔진보다 자기 블로그를 먼저 열게 되고, 블로그는 실제 도메인에서 HTTPS로 운영되며, push하면 자동으로 배포된다.

## 2. 목표 / 비목표 / 실패 조건

**목표**
- 주제별로 정리된 공개 학습 노트 사이트(위키형)
- Claude Code에 요청하면 노트가 생성되거나 기존 노트가 보강됨. 검토 없이 즉시 공개
- Google 로그인 기반 댓글, 관리자 편집 화면
- 노트 이전 버전 기록과 복원
- 노트에 이미지 첨부
- AWS Lightsail에 Docker로 배포, 내 도메인 + HTTPS, GitHub Actions 자동 배포
- 진행하면서 각 단계의 개념을 사용자에게 설명함

**비목표 (이번 범위에서 제외)**
- 대화가 끝날 때마다 자동으로 기록하는 훅. 업로드는 사용자가 요청할 때만 한다.
- 타임라인형 블로그나 학습 로드맵 화면
- 별도의 프론트엔드 프레임워크(React 등)
- 여러 작성자, 아이디/비밀번호 회원가입

**실패 조건 (동작은 해도 실패로 보는 경우)**
- API 키, 비밀번호, 토큰, 회사 내부 코드나 이름 같은 민감 정보가 공개 노트에 그대로 노출됨
- 노트가 쌓일수록 찾기 어려워짐. 중복 노트가 난립하는 경우가 대표적이다.
- 사용자가 무엇을 왜 하는지 모른 채 배포가 끝남. 학습 목표를 놓친 것이다.
- 월 비용이 1만 2천 원 수준을 크게 넘음

## 3. 제약

- 예산: Lightsail 1GB 플랜(공인 IPv4 포함 월 약 $7)과 도메인(연 1~2만 원)을 합쳐 월 1만 1천~2천 원 수준까지 사용자가 수용했다. 그 외에는 무료이거나 월 수백 원 이하인 것만 쓴다. AWS 신규 가입 크레딧이 있으면 활용한다.
- 서버 메모리가 1GB이므로 Spring Boot와 PostgreSQL이 함께 돌아가야 한다. 스왑을 설정하고 JVM 힙을 제한한다.
- 개발 환경은 Windows 11 + Claude Code다.
- 프로젝트 위치는 `C:\workspace\saip`이며 아직 git 저장소가 아니다.

## 4. 사용자가 정한 것

| 항목 | 결정 |
|---|---|
| 업로드 시점 | 사용자가 Claude Code에 요청할 때만 (자동 훅 없음) |
| 공개 방식 | 검토 없이 즉시 공개, 나중에 수정 가능 |
| 민감 정보 | 치환해서 올림 (예: `[API_KEY]`, `[PASSWORD]`, `[COMPANY_CODE]`) |
| AI 처리 위치 | 내 PC의 Claude Code가 글을 완성하고, 블로그 서버는 저장과 표시만 함. Claude API 사용 안 함 |
| 노트 단위 | 주제별. Claude Code가 기존 노트를 읽고 "새 내용이면 생성, 아니면 기존 노트 보강"을 판단함 |
| 화면 방향 | B안 주제별 노트(위키형): 왼쪽 주제 트리 + 본문 |
| 마크다운 | 기능이 풍부하고 보기 좋게 렌더링 |
| 로그인 | Google 로그인. 관리자 화면과 댓글에 사용 |
| 관리자 화면 | 필요함. 웹에서 노트 작성·수정·삭제 |
| 댓글 | 필요함 |
| 백엔드 | Spring Boot (사용자 주력 기술) |
| 클라우드 | AWS Lightsail 1GB. 도메인 포함 월 1만 1천~2천 원 수준 수용 |
| 스택 규모 | Spring Boot + PostgreSQL 유지 (오버 스펙 여부 논의 후 결정) |
| 버전 기록 | 노트 수정 시 이전 버전 기록, 관리자 화면에서 비교·복원 |
| 이미지 | 노트에 이미지 첨부 가능, 비용이 늘지 않는 방식으로 |
| 진행 방식 | 한 단계씩, 무엇을 왜 하는지 친절히 설명하면서 진행 |

## 5. 설계자(Claude)가 정한 것

사용자가 동의한 것이 아니라 설계자의 판단이다. 사용자는 문서 검토 때 확인한다.

**기술 스택**
- Java 21, Spring Boot 4.1.x (계획 작성 시점 start.spring.io 기본 버전, 3.x는 무료 지원 종료), Gradle
- Thymeleaf 서버 렌더링. 학습의 무게를 배포 쪽에 두기 위해서다.
- PostgreSQL. 로컬 개발도 Docker로 띄운 PostgreSQL을 쓴다.
- Spring Security OAuth2 Client로 Google 로그인
- Docker 이미지, GitHub Container Registry(무료)
- AWS Lightsail 인스턴스 1대. 그 위에 docker compose로 앱, DB, Caddy를 실행
- Caddy로 리버스 프록시와 HTTPS 인증서 자동 발급
- GitHub Actions로 테스트, 이미지 빌드, 서버 배포

**권한 모델**
- 로그인은 Google 하나뿐이고 비밀번호를 저장하지 않는다.
- 설정값(환경변수)에 등록된 관리자 이메일로 로그인하면 관리자다. 관리자는 노트 CRUD, 모든 댓글 삭제, 편집 화면 접근 권한을 가진다.
- 그 외 Google 사용자는 댓글을 작성하고 자기 댓글을 수정·삭제할 수 있다.
- 비로그인 방문자는 노트와 댓글을 읽기만 한다.
- Claude Code는 사람이 아니므로 별도 API 토큰(Bearer, 환경변수로 설정)으로 노트 API를 호출한다. 이 토큰은 노트 조회·생성·수정과 이미지 업로드만 허용하고 댓글이나 삭제는 허용하지 않는다.

**콘텐츠 구조**
- 2단계 구조다. **주제(Category)**는 사이드바의 큰 묶음(예: 배포, Spring, AI)이고, **노트(Note)**는 그 아래 개별 문서(예: Docker, JPA)다.
- 노트는 제목, slug, 주제, 마크다운 본문, 생성일, 수정일을 가진다. 수정될 때 본문이 보강되는 "살아 있는 문서"다.
- 주제가 없으면 Claude Code가 노트를 올리면서 새로 만들 수 있다.
- 댓글은 노트에 달린다. 대댓글은 넣지 않는다.
- 노트가 수정될 때마다(웹 편집과 API 모두) 이전 본문을 버전 테이블에 남긴다. 관리자 화면에서 버전 목록, 현재 본문과의 차이 보기, 복원을 제공한다. 복원도 하나의 수정으로 기록한다.
- 이미지는 Lightsail 디스크(볼륨 마운트)에 저장한다. 업로드할 때 긴 변을 제한하고 WebP 등으로 압축한다. 관리자 편집기(붙여넣기, 드래그)와 토큰 API 양쪽에서 업로드할 수 있고, 노트 본문에서는 마크다운 이미지 문법으로 참조한다. Claude Code 스킬은 사용자가 대화에 첨부한 스크린샷 등을 올릴 수 있다.

**화면**
- 공통 레이아웃: 상단 바(사이트명, 검색, 로그인), 왼쪽 주제 트리, 본문
- 첫 화면: 최근 수정된 노트 목록
- 노트 화면: 본문, 마지막 수정일, 오른쪽 자동 목차, 하단 댓글
- 검색: 제목과 본문 검색. 처음에는 PostgreSQL 기본 검색으로 충분하다.
- 관리자 편집 화면: 마크다운 편집기와 실시간 미리보기, 주제 선택, 삭제. 댓글 관리 목록
- 모바일에서 사이드바는 접힌다.

**마크다운 기능**
- GFM: 표, 체크리스트, 취소선, 자동 링크
- 코드 하이라이팅과 복사 버튼
- 강조 박스(팁, 주의, 정보)
- Mermaid 다이어그램
- 제목 기반 자동 목차
- 공개 화면과 편집기 미리보기가 같은 결과로 렌더링되어야 한다.

**Claude Code 연동**
- 사용자 레벨 Claude Code 스킬 하나(예: `/blog`). 어느 프로젝트에서 대화하든 쓸 수 있어야 하므로 `~/.claude/skills/`에 둔다.
- 블로그 주소와 API 토큰은 환경변수로 받는다. 배포 전에는 `localhost`, 배포 후에는 실제 도메인을 가리킨다.
- 스킬의 동작 순서:
  1. 현재 대화에서 배운 내용을 파악한다.
  2. API로 주제와 노트 목록을 조회하고, 관련 노트가 있으면 본문을 읽는다.
  3. 새 노트를 만들지, 기존 노트를 보강할지 판단한다. 보강할 때는 기존 내용을 지우지 않고 통합한다.
  4. 마크다운 기능(코드, 표, 강조 박스, Mermaid)을 활용해 작성한다.
  5. 민감 정보를 치환한다.
  6. 전송 직전에 로컬에서 패턴 검사를 한 번 더 한다(키 형태 문자열, `password=`, 사설 IP, 토큰 등). 걸리면 치환한 뒤 보낸다.
  7. 업로드한 다음 "새로 만듦 / 기존 노트 수정함"과 노트 링크를 한 줄로 알린다.
- 서버 쪽에서도 노트 API(토큰 API)로 들어온 본문에 같은 일반 패턴 검사를 적용해 이중 방어한다. 패턴이 걸리면 저장하지 않고 422와 함께 걸린 위치를 돌려준다. 스킬은 그 부분을 치환해 다시 보낸다. 관리자 웹 편집기와 댓글에는 이 검사를 적용하지 않는다. 사람이 직접 쓰는 글이기 때문이다.
- 회사명이나 내부 코드처럼 정규식으로 잡을 수 없는 단어는 사용자 PC의 로컬 파일(예: `~/.claude/blog-redact.txt`)에 목록으로 둔다. 스킬만 이 파일을 읽으며, 저장소나 서버에는 올리지 않는다.

**저장소와 백업**
- GitHub 저장소는 공개(public)로 둔다. Actions 사용 시간과 ghcr 이미지가 무료이고, 서버에서 이미지를 받을 때 로그인할 필요가 없으며, 포트폴리오로도 쓸 수 있다. 비밀값은 전부 GitHub Secrets와 서버 환경변수에 두고, 저장소에는 `.env.example`만 둔다. 비공개를 원하면 바꿔도 계획은 크게 달라지지 않는다.
- 백업은 서버에서 매일 pg_dump 결과와 이미지 폴더를 압축해 S3에 보관한다. 보관 기간을 제한해 비용을 월 백 원 안쪽으로 유지한다.

## 6. 진행 단계

각 단계는 "개념 설명 → 함께 구현 → 동작 확인 → 그 단계에서 배운 노트 작성" 순서로 진행한다. 단계 설명은 사용자가 처음 접한다고 가정하고, 이 도구가 무엇이고 왜 필요한지와 대안이 무엇인지부터 시작한다.

1. **로컬 개발 환경**: git 저장소 생성, Spring Boot 프로젝트, Docker로 띄운 PostgreSQL
2. **노트 공개 화면**: 주제 트리, 노트 보기, 마크다운 렌더링, 검색
3. **노트 API와 Claude Code 스킬**: 토큰 인증, 조회·생성·수정 API, 민감 정보 검사, `/blog` 스킬. 이 단계부터 로컬 블로그에 노트를 쌓기 시작한다.
4. **Google 로그인, 관리자 편집 화면, 댓글, 버전 기록, 이미지 업로드**
5. **Docker로 포장**: Dockerfile(멀티스테이지), docker compose. ARM과 x86 차이가 있으면 이 단계에서 다룬다.
6. **AWS Lightsail**: 인스턴스 생성, SSH, 방화벽, 고정 IP, 스왑, docker compose로 실행. 로컬 DB의 노트를 서버로 옮긴다(pg_dump/restore).
7. **도메인과 HTTPS**: 도메인 구매, DNS 연결, Caddy. Google OAuth 리디렉션 주소를 실제 도메인으로 등록한다.
8. **GitHub Actions 자동 배포**: push → 테스트 → 이미지 빌드 → 서버 반영. 비밀값은 GitHub Secrets로 관리한다.
9. **운영 기본기**: DB 백업 자동화, 로그 확인 방법

## 7. 구현자에게 맡기는 것

- 마크다운 렌더링을 서버(commonmark-java 등)에서 할지, 클라이언트(markdown-it 등)에서 할지. 단, 공개 화면과 편집기 미리보기 결과가 같아야 한다.
- 편집기 라이브러리 선택
- 화면의 구체적인 디자인(색, 글꼴, 다크 모드 여부)
- 테이블 스키마 세부, API 경로 이름, 패키지 구조
- 민감 정보 패턴 목록의 구체적인 내용
- 도메인 등록처 추천(Route 53, 가비아, Cloudflare 등)

## 8. 기타

- 아직 git 저장소가 아니므로, 이 문서는 1단계에서 저장소를 만들 때 첫 커밋에 포함한다.
- `.superpowers/` 폴더는 `.gitignore`에 포함한다.
