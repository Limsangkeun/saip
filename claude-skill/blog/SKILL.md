# 학습 노트 올리기

대화에서 배운 내용을 사용자의 학습 블로그에 노트로 올린다. 노트는 바로 공개되므로 비밀값이 절대 들어가면 안 된다.

도구: `python ~/.claude/skills/blog/blog.py <명령>` (환경변수 `BLOG_URL`, `BLOG_TOKEN` 필요)

| 명령 | 하는 일 |
|---|---|
| `list` | 노트 목록 JSON (slug, title, categorySlug, categoryName) |
| `get <slug>` | 노트 본문 JSON |
| `create <file.json>` | 새 노트 |
| `update <slug> <file.json>` | 기존 노트 덮어쓰기 (이전 버전은 서버에 자동 보관) |

종료 코드 0은 성공, 1은 오류, 2는 민감 정보가 걸린 것이다(로컬 검사 또는 서버 422). 환경변수가 없으면 사용자에게 설정을 요청하고 멈춘다.

## 순서

1. **배운 내용 파악**: 이 대화에서 사용자가 새로 알게 된 개념, 결정과 그 이유, 실제 명령과 코드, 겪은 문제와 해결을 추린다. 사용자가 주제를 지정했으면 그것만 다룬다.
2. **기존 노트 확인**: `list`를 실행하고, 주제가 겹치는 노트가 있으면 `get`으로 본문을 읽는다.
3. **새로 만들지, 보강할지 판단**: 같은 주제의 노트가 있으면 보강한다. 다른 주제면 새로 만든다. 카테고리도 기존 것을 우선 재사용하고, 맞는 게 없을 때만 새 `categorySlug`(영문 소문자, 하이픈)와 `categoryName`(한글)을 정한다.
   - 보강할 때는 **기존 내용을 지우지 않는다**. 알맞은 섹션에 끼워 넣거나 섹션을 추가하고, 겹치는 설명은 하나로 다듬는다.
4. **작성**: 처음 보는 미래의 내가 읽어도 이해되게 쓴다. 순서는 **개념 → 왜 필요한지 → 실제 명령·코드 → 겪은 문제와 해결**이다. 한국어로 쓴다.
   - 마크다운 기능을 적극 쓴다: 언어를 붙인 코드 블록, 표, 체크리스트(`- [ ]`), ` ```mermaid ` 다이어그램, 강조 박스(`> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`, `> [!CAUTION]`).
   - 제목은 `# `로 다시 쓰지 않는다(화면이 제목을 따로 보여준다). 본문 섹션은 `## `, `### `로 시작한다. 목차가 이걸로 만들어진다.
5. **민감 정보 치환**: 실제 값은 아래 자리표시자로 바꾼다.

   | 대상 | 자리표시자 |
   |---|---|
   | API 키 | `[API_KEY]` |
   | 비밀번호 | `[PASSWORD]` |
   | 토큰 | `[TOKEN]` |
   | 사설 IP | `[PRIVATE_IP]` |
   | 회사명·고객사명 | `[COMPANY]` |
   | 사내 시스템·코드명 | `[INTERNAL_CODE]` |

   회사 내부 코드는 그대로 옮기지 않는다. 개념만 남기고 일반화한 예제로 다시 쓴다.
6. **전송**: `{"title", "categorySlug", "categoryName", "body"}` JSON을 임시 파일에 UTF-8로 쓰고(명령줄 인자로 본문을 넘기지 않는다) `create` 또는 `update`를 실행한다.
   - 종료 코드 2면 `findings`의 `line`에 해당하는 줄을 치환해 다시 보낸다. **1번 줄은 제목, 본문은 2번 줄부터**다. 로컬 검사의 `redact_word`는 회사 금지어(`~/.claude/blog-redact.txt`)에 걸린 것이다.
   - 서버 422도 같은 번호 규칙이므로 똑같이 처리한다. 409(제목 중복)면 기존 노트를 보강하거나 제목을 바꾼다.
   - 전송이 끝나면 임시 파일을 지운다.
7. **보고**: 한 줄로 알린다. 예: `새로 만듦: Docker 기초 (http://localhost:8080/notes/docker-기초)` 또는 `기존 노트 수정함: Flyway (url)`.
